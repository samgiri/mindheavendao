# Contributing

## Scope protection

The approved Homepage V3 is frozen. Documentation pull requests must not modify `app/`, `public/`, website configuration, lockfiles, or deployment settings. Website changes require a separate, explicitly authorized request.

## Documentation changes

1. Create a focused branch and explain the decision or clarification being proposed.
2. Distinguish confirmed decisions from recommendations and open questions.
3. Update `docs/decisions/DECISION_LOG.md` when a decision is ratified.
4. Update `docs/decisions/OPEN_DECISIONS_REGISTER.md` when an item changes status.
5. Update `CHANGELOG.md` for material documentation changes.
6. Check all internal links, Mermaid syntax, terminology, numbers, and basis-point conversions.

## Required language boundaries

Do not claim guaranteed returns or APY, describe Founder Nodes as company equity, call referral rewards passive income, make unsupported medical claims, imply that recommendations are approved, or present unaudited specifications as production-ready.

## Review requirements

Protocol documentation requires governance review. Relevant sections also require legal, security, economic, privacy, and health/ethics review. Production smart contracts must be developed and audited in a later, separately approved phase.

By contributing, you agree not to include secrets, personal data, private keys, medical records, or confidential evidence.
